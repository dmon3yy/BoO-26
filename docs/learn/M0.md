# M0 — How this works

**TL;DR:** The game is built like a theatre company. `content/` is the **script** (plain text you can edit), `tools/` is the **workshop** that turns the script into sets, costumes and an orchestra (Python), and `game/` is the **stage** where it all performs (Godot). Tests are the **dress rehearsal**: they run before you ever see a build.

## The three folders

| Folder | Role | Language | You'd edit it to… |
|---|---|---|---|
| `content/` | The script | Plain text / JSON | Move a platform, retime a melody, rewrite a line of dialogue, tune a jump |
| `tools/` | The workshop | Python | Change *how* art and music are generated |
| `game/` | The stage | GDScript | Change how the game behaves |

The key idea: **content is data, not code.** A room is a text picture; a song is a text score; Orpheus's jump is a number. That's why Claude can build and test everything here, and why you can change a lot without touching code.

## Following one room from text to screen

Open `content/rooms/arcadia_01.room`. Each character is one 16×16 tile: `#` rock, `%` marble, `=` a ledge you can jump up through, `P` where Orpheus starts, `H` a Hearth, `T` a torch, `Y` an olive tree. The `[back]` section paints the dark back walls.

When the game enters a room, `game/world/room_builder.gd` reads that text and builds it in five passes:

1. **Tiles.** For each rock tile it looks at the eight neighbours (`autotiler.gd`) and picks one of 47 shapes, so edges, corners and snow caps land in the right place. It also picks one of 16 "macro variants" by position, so the rock texture flows across tiles instead of repeating.
2. **Collision.** `outline.gd` traces the outline of all the solid tiles into a few long lines. Orpheus walks on those lines, so he never snags on seams between tiles.
3. **Shadows.** The same outlines become light occluders, so torches cast real shadows.
4. **Props and lights.** Each letter like `T` is looked up in `content/props.json`, which says which picture to draw, where its flame goes and what light it gives.
5. **Theme.** `content/themes.json` decides what `#` means in this place (limestone and snow in Arcadia, basalt in Erebos), the backdrop layers, the ambient colour, the weather and the music.

**The validator is the safety net.** `tools/validate_world.py` reads the same room files and checks three things:
- whether every item can be reached,
- whether neighbouring rooms' openings line up,
- whether any spot can **trap** you: no way back to a Hearth, and no hazard to die on and respawn.

It already caught five of Claude's own mistakes in M0, including an olive five tiles above any ledge and a pit behind the temple you couldn't climb out of.

## How Orpheus moves, and why the tests trust it

All of Orpheus's physics is one small function, `Orpheus.step_motion()`. Given his speed, the controls and a sliver of time, it returns his new speed. Because it's a pure function (same inputs, same output, no side effects), three different places can use the *exact same physics*:

- **The game:** 60 times a second.
- **The tests** (`tests/unit/test_movement.gd`): they simulate a jump and check it really clears 3 tiles up and 4 across.
- **The validator:** it trusts those same limits when deciding what's reachable.

Change `jump_velocity` in `content/movement.json` and all three stay in agreement. If the jump gets too weak for the declared limits, a test fails before you ever play it.

## How the music keeps time

Music is written as text scores (`content/music/*.score`): scale degrees on a 16-step grid, one line per bar. `tools/build_audio.py` is a small synthesizer:
- the lyre is a plucked-string simulation (Karplus–Strong)
- the bass is FM synthesis
- the anvils are clashing metal frequencies

It writes each part as its own **stem** (melody, harmony, percussion). All stems are exactly the same length, so they can be layered later, for example adding drums when a fight starts.

In the game, `game/autoload/music.gd` keeps a **clock**. It doesn't trust the audio position alone, because that only updates in chunks. It runs its own smooth clock from frame time and gently steers it toward the audio. That clock is what decides PERFECT, GOOD or MISS when you press a button.

Your **calibration offsets** correct for your speakers and screen: the audio offset, the visual offset and the input offset.

**Known nit:** on quit, Godot prints a warning that the music streams were "still in use" (the audio thread holds them a moment). It's harmless.

## Try it yourself (5 minutes each)

1. **Move a ledge.** In `content/rooms/arcadia_01.room`, move one of the `=` ledges up a row. Run `python3 tools/validate_world.py`. Did the validator object? (It will if the olive becomes unreachable.)
2. **Make Orpheus floatier.** In `content/movement.json`, change `gravity` from 980 to 800. Run the tests: are the declared limits still met? Then raise `limits.jump_height_tiles` to 4 and watch the validator's verdicts change.
3. **Swing the arms harder.** In `content/rigs/orpheus.json`, under `run`, raise `uarm_f.amp` and `uarm_b.amp` from 34 to 50. Run `python3 tools/build_character.py` and look at `game/art/characters/orpheus.png`.
4. **Rewrite Zeus.** Edit `content/dialogue/zeus.dialogue`. Press **F4** in the game to see it.
5. **Retime the grove.** In `content/music/arcadia.score`, change `bpm = 84` to `72`. Run `python3 tools/build_audio.py arcadia`, then open the Beat Lab and switch songs with Lyre (Shift).

## Commands

```bash
python3 tools/build_all.py            # regenerate every asset (art, font, music)
python3 tools/validate_world.py       # check the world
python3 -m pytest -q tests/python     # Python tests
godot --headless --import             # let Godot import new assets
godot --headless -s addons/gut/gut_cmdln.gd -gdir=res://tests/unit -ginclude_subdirs -gexit   # engine tests
```

**In the game:**

| Key | Does |
|---|---|
| Arrows / WASD | Move |
| Z / Space | Jump |
| X | Attack (later) |
| Shift | Lyre (later) |
| F2 | Next test room |
| F3 | Beat Lab |
| F4 | Test dialogue |

**On the web:** add `?lab` to the address to open straight into the Beat Lab.

## Key takeaways
- Data drives everything: rooms, songs, poses and physics are text you can change.
- One source of truth per rule (movement, room grammar, beat maths) is shared by the game, the tests and the validator.
- Your job at the M0 gate: **judge the look** (screenshots) and **feel the beat** (Beat Lab on your own device).
